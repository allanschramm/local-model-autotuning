# ADR 0017: Rank Membership — Every Complete Model, Quality-First; Domination Is Same-Model Only

**Date:** 2026-08-26
**Status:** Accepted (operator decision). **Supersedes in part:** [0006](0006-pareto-frontier-search.md) (cross-model front membership), [0009](0009-day-profile-tps-floor.md) / [0013](0013-agentic-coding-night-selector.md) (profile floors become sort keys, not admission filters). Implementation lands in `scripts/rank_results.py`, `autoresearch/core/recompute.py`, `autoresearch/core/classify.py`, and the leaderboard docs; leaderboards are regenerated by the tool at that time, never hand-patched.

## Context

The stored `dominated` status was defined as cross-model strict-Pareto loss (ADR 0006): any complete vector in the hardware+budget bucket beating another on all four axes demoted it. Consequence observed 2026-08-26: quality-tied slower models vanished from the Day/Night tables entirely (Tiel-Coder 35B at agentic 0.8667 / coding 0.6400 hidden), while a much weaker model stayed listed on the strength of a TPS axis maximum alone. The operator rejected cross-model domination outright and re-stated the design intent of the ranked report.

## Decision

1. **The rank is a leaderboard, not a frontier.** Every model with a complete Objective Vector appears exactly once in both Day and Night tables — no exclusions for being beaten by another model.
2. **Representative Trial per model:** each model's row is its single best measured Trial, selected by highest `iq_min = min(agentic, coding)` among its complete Trials. Its ctx / TPS columns show that Trial's actual values (never merged best-per-axis).
3. **Ordering quality-first:** sort by `iq_min` descending with a **±0.05** near-tie band. Within a band, a model clearly superior in agentic and coding (Pareto quality-dominance) can never be leapfrogged. For quality ties and non-dominated trade-offs, the lens breaks ties: Day orders by higher TPS (then ctx); Night orders by larger ctx (and if ctx is tied, by higher quality: `iq_min`, `agentic + coding`). Speed or context is strictly a **tie-breaker (critério de desempate)** and never demotes a model clearly superior in agentic and coding (Tiel-Coder sits at #2 on both tables).
4. **Floors demoted to history:** `DAY_TPS_FLOOR` and `NIGHT_CTX_FLOOR` no longer filter membership anywhere. They may survive as documented *lens* notes, nothing more.
5. **Domination is redefined as a same-model config label** — it exists only inside one GGUF basename's config A/B comparisons (the MTP vs cache vs MTP+cache style verdicts). Cross-model `dominated` labels cease to exist going forward; `results.db` labels are relabeled accordingly when implementation lands (mandated).
6. **Incomplete models stay out of the rank** until their vector completes — invisibility applies only to unfinished evaluations, never to finished-but-slower ones.
7. **Autoloop seeds only from an operator-named model (`--models`).** The `--profile day|night` auto-pick path contradicts the contract "the user picks the model, always" and is slated for removal or interactive confirmation when implementation lands.
8. `pick_day` / `pick_night` conform to the new ordering automatically once tables change; today's #1 under both old and new math is unchanged (Qwen3.8-4B).

## Consequences

- Tiel-Coder, Ornith-1.5-35B, KAT-Coder, POCKET-35B etc. return to both tables; LFM2.5-8B sorts to the bottom of completed models rather than masquerading mid-table.
- The pure nucleus (`pareto.dominates`) stays untouched; scope selection changes at call sites only.
- Leaderboard docs intentionally lag until the generator implements this ADR (no hand patches).
