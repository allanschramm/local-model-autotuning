The effective server command contained `--spec-type draft-mtp --spec-draft-n-max 2`. Runtime statistics confirmed embedded MTP activity with draft acceptance, rather than flags alone.

- Bare `--spec-type mtp` was rejected by this runtime; its accepted token is `draft-mtp`.
- Batch/ubatch `64/32` reached 7910 MB and was rejected by the physical-VRAM gate during BigCodeBench.
- One detached attempt inherited a launcher output pipe that closed early and ended with `[Errno 22] Invalid argument`; durable redirection removed that infrastructure failure without changing the model settings.

- Keep `32/16` for this 100k MTP Fingerprint; it completed below the physical-VRAM gate.
- Preserve rejected infrastructure and VRAM rows in `results.tsv`.
- Do not sweep MTP n=4 until a separate config-only Trial proves it fits the same physical-VRAM limit.
