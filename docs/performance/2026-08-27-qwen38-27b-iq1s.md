Historical runtime failure: the model process was killed mid-workload; tool-prompt prefill was **3.5 t/s** and turn requests timed out.
- **CORRECTED (operator observed VRAM the whole run, peak ~7.7 GB):** the "VRAM creep"
  diagnosis was WRONG. The watchdog (llama_runner.py:1255) measures device-wide
  `nvmlDeviceGetMemoryInfo.used` — model + Windows desktop combined — and attributes it to
  the dense model. At minute ~48 a device-wide sample (8108 MB = ~7.7-7.9 GB model + desktop
  variance) crossed the 8100 ceiling and the watchdog killed a HEALTHY server. The model
  never OOM'd, spilled, or crashed on its own. With keepout 88, the entire desktop had only
  88 MB allowance — DWM fluctuation alone can blow that.
- Task failures (0/5) are real but caused by per-turn client timeouts at 3.5 t/s prefill
  (`turn N request failed: timed out`), not model death.
- Model-side truth: fits at 64k (~7.7-7.9 GB vs <physical-limit> MiB) with desktop kept lean;
  device-wide watchdog will false-kill at any tight ceiling when desktop VRAM fluctuates.
