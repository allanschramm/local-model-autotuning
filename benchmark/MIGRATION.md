# Evaluation migration

Runtime optimization belongs to `autoresearch/tuning.py`; quality evaluation belongs here. A local model endpoint is the primary validation target. Cloud validation is deferred. Both modules remain in this repository until the operator moves it to the AILOCAL organization.

## Verifier correction and score identity

The legacy HumanEval path returns the dataset's `test` text and concatenates it after model code. In the inspected snapshot that text defines `check(candidate)` but never calls it. Merely defining that function can exit successfully even for an incorrect implementation. It also does not execute the dataset's `plus_input` cases.

The migrated hidden pytest keeps the original assertion text and explicitly calls `check` on the function imported from `solution.py`. Every unimplemented stub must fail and every upstream canonical solution must pass in the standalone E2E. Oracle sources are outside the model's allowlisted workspace.

MBPP's inspected legacy path already executes its `assertion` field; it does not execute `plus_input`. The migrated pack imports the same entrypoint from `solution.py` and wraps those literal assertions in pytest. Its first ten IDs are not contiguous and include original prompting examples, so label it a legacy-selected base smoke subset, not a standard test-split score. The same fail-stub/pass-oracle E2E applies to all ten tasks.

Preserved dataset limitation: Mbpp/2's public prompt compares sets, while its hidden base assertions require a literal tuple. The pack does not normalize that mismatch. Keep task-failure interpretation distinct from model-runtime or harness failures.

LiveCodeBench's new slice preserves the legacy private-only, exact-stdout-after-newline-stripping grading rule. Public cases remain examples in the prompt, not a second scoring set. Unlike the upstream grader, it neither adds public cases to the score nor performs broader whitespace/numeric normalization. The official `release_v6` aggregate is larger than the single `test6.jsonl` increment used by this checkout. Ten selected stdin tasks are not an official full-dataset score.

The pinned source's base64/zlib/pickle wrapper is decoded without executing pickle: accept exactly one JSON string through a literal opcode whitelist, then validate the case schema. Frozen gzip JSON replaces that serialization at runtime. Each case runs in a fresh cwd/process. No automatic execution timeout is added; initial local validation targets the four easy tasks. No upstream gold solutions are provided, so E2E validates the stdin machinery using a known first-problem solution and negative controls rather than claiming ten canonical-solution passes.

New results retain `pi-workspace-v2` because the Pi tools, prompts and budgets are unchanged. Run configuration identifies the pack; task hashes identify its exact prompts and verifiers. Do not pool these results with legacy HumanEval columns or claim retrospective validation of historical coding scores. Existing SQLite rows are not rewritten.

## Compatibility and retirement

DM-Code-Agent's new `pi-dm-v1` protocol freezes all 30 tasks at the existing pinned revision, including source order and every loader field. Pi replaces mini-swe-agent; existing file adapters plus a fixed public pytest tool cover this corpus without unrestricted shell execution. Only initial setup paths are accessible, plans stay in responses, source max steps become Pi turn limits, and hidden fixtures appear only after the agent in a separate copy. Preserve the scope diff before staging so allowed/required file constraints remain independent of green tests. SQLite stores the scope/hidden verdict separately from weighted Claw grading. The legacy mini-swe-agent entrypoint and category remain intact.

Grader correction: generated packaging configuration can set pytest `addopts` to select a single passing public test while the implementation still fails hidden requirements. The migrated hidden verifier overrides pytest discovery configuration with a trusted empty ini, retaining the original command prefix and file bytes. Public test execution still uses workspace configuration. The E2E reproduces and rejects the bypass. This is a new Pi protocol, not an assertion of upstream-agent or mini-swe-agent score parity; source fixture compatibility and four upstream reference controls are verified separately from actual model quality.

Claw uses `pi-claw-v2`, separate from workspace generation and historical `pi-claw-v1` scores. Preserve the legacy 5/15 selection, original prompts/schemas, deterministic completion weights and threshold 0.5. The pinned checkout's full tier actually contains ten offline tasks and five `web_real` tasks requiring external search. Never silently replace them with mocks or include unavailable tasks as quality zeroes. Live web requires explicit enablement and a key; local validation may report the ten offline measurements with five infrastructure/unmeasured outcomes.

Security ownership: v2 moves the original web server into the maintained `claw_web.py` adapter, recording its original SHA-256 in `adapter_sources`. Other frozen files stay byte-identical. Every fetch/redirect resolves and validates all addresses before a connection pinned to one public IP; TLS keeps the original host identity. Block nonstandard ports, transition/private IPs, environment proxies and compressed/unbounded bodies. HTMLParser replaces regex extraction, and tool errors omit internal exceptions. The ASGI/transport/real-bridge regressions retain their own SQLite evidence inside Claw E2E. The upstream checkout is untouched; CodeQL scans the actual adapter, with no finding suppression or vendored-path exclusion.

The upstream apps now run in a fresh per-task Python process through FastAPI TestClient/ASGI, preserving endpoint validation/reset/state without fixed listening ports. Pi replaces only the legacy agent loop. Its fixed budgets and lack of retries/pruning/continuation differ from legacy recovery behavior. Completion grading remains narrow and can credit keyword mentions or failed tool invocations. The old adapter ignored all safety declarations; the new protocol vetoes explicitly forbidden tool calls, retains raw completion scores and reports unsupported semantic safety checks as unevaluated. Neither protocol represents the upstream full custom graders or Pass^3 metric. Scores and component details live in SQLite; no legacy scores are rewritten.

BigCodeBench Hard freezes v0.1.4 IDs /13, /15, /17, /19, /34, /37, /82, /89, /92 and /93 in legacy order. The source instruct prompt and original TestCases text stay intact; the workspace starts with the source code prompt plus an unimplemented stub. Hidden pytest executes solution and tests in one module namespace, then explicitly runs the entire unittest suite. This preserves tests that refer to solution imports and global objects. Graphs use Agg; the legacy Windows normalization of shell `not found`/`not recognized` assertions remains scoped to suite execution. Missing libraries/fixture files are infrastructure failures. Direct dependency pins are a validated environment reference, not an official leaderboard environment or complete transitive lock. No automatic execution timeout or OS sandbox is added.

The independent runner never imports legacy evaluation, and the tuning module never invokes Pi. Legacy consumers have different retirement requirements:

| Consumers | Dependency | Retirement condition |
| --- | --- | --- |
| `runners/evaluation.py`, `runners/run.py`, `benchmark_search.py`, `scripts/lcb_only.py` | Historical execution and operator commands | Explicit workflow deprecation; never silently redirect old flags to Pi protocols |
| Operator-only `autoloop.py` | Legacy benchmark configuration | Migrate its configuration ownership before removing that module; do not launch the loop as a compatibility check |
| `benchmarks/__init__.py` | Public function/class exports | Preserve all 14 symbols and original object identities; runners load on access, catalog/config remain lightweight |
| Dashboard, rankings, `core/trial_store.py`, recompute/classification | Historical SQLite rows and protocol identity | Keep historical schemas/readers; these do not require the legacy agent loops |
| Legacy runner/protocol tests | Old execution and compatibility coverage | Retire alongside the corresponding workflow, preserving store/protocol integrity checks |

Run `scripts/test_legacy_consumers_e2e.py` with the repository venv before retirement. It copies public sources/config outside the checkout, blocks evaluation imports for catalog/config and read-only consumers, checks exports plus actual operator CLI listing/help, and serves dashboard HTTP against a synthetic SQLite-only store. Its retained `results.db`, `ranking.txt`, `dashboard.json`, `imports.json` and `verification.json` show unchanged historical rows and exclusion of independent Pi/tuning tables. The AST inventory covers copied production sources, not dynamic imports or all tests; review those callers separately before deletion.

Before retiring a legacy path: port all selected tasks and verifier behavior, publish its protocol identity, run a local endpoint end to end with SQLite/trajectory evidence, and check every caller plus the commands documented for operators. Historical result tables/protocols remain readable. A passing small pack alone does not authorize deleting all old evaluations.

## Open-source approaches considered

- [safehttpx](https://github.com/gradio-app/safehttpx) uses a pinned-IP HTTP transport and refuses automatic redirects. Its current implementation adds another HTTP client stack. Reuse installed [urllib3's documented custom SNI/IP connection](https://urllib3.readthedocs.io/en/stable/advanced-usage.html#custom-sni-hostname), preserving hostname/certificate validation and explicitly revalidating each redirect. The current Claw upstream web server still has the original unsafe fetch/filter/error paths, so it cannot supply this fix unchanged.

- [PEP 562](https://github.com/python/peps/blob/main/peps/pep-0562.rst) supplies module attribute/inspection hooks; [scientific-python lazy-loader](https://github.com/scientific-python/lazy-loader/blob/main/src/lazy_loader/__init__.py) uses them for deferred exports. Reuse the existing repository's module-hook pattern with stdlib `importlib` for the six legacy functions, preserving their identity without another dependency.

- [EvalPlus data loader](https://github.com/evalplus/evalplus/blob/master/evalplus/data/humaneval.py) distinguishes original `test`, `base_input`, expanded `plus_input`, and oracle solutions. Use the existing pinned snapshot; do not relabel its base tests as plus coverage.
- [Harbor HumanEvalFix adapter](https://github.com/harbor-framework/harbor/tree/main/adapters/humanevalfix) demonstrates dataset-to-workspace adaptation with separate verification and oracle assets. Its repair dataset and container runtime differ from our existing generation tasks; adopting its whole execution stack is unnecessary for this slice.
- [EvalPlus MBPP loader](https://github.com/evalplus/evalplus/blob/master/evalplus/data/mbpp.py) preserves source IDs and deserializes inputs; [EvoAgentX's MBPP adapter](https://github.com/ANative-Lab/EvoAgentX/blob/main/evoagentx/benchmark/mbpp.py) converts raw MBPP to HumanEval-shaped prompts and checks. Our legacy already consumes EvalPlus's normalized snapshot, so reuse that exact data and the existing Pi workspace runner without another dataset remapping.
- [Official LiveCodeBench loader](https://github.com/LiveCodeBench/LiveCodeBench/blob/main/lcb_runner/benchmarks/code_generation.py) distinguishes functional/stdin tests and combines public/private cases for official evaluation. [Harbor's LiveCodeBench adapter](https://github.com/harbor-framework/harbor/tree/main/adapters/livecodebench) supplies full containerized task execution and broader output normalization. This slice reuses the existing Pi workspace runner with hidden stdin verification and preserves the current legacy's narrower grading contract; neither an extra agent loop nor the whole container stack is needed for the initial local smoke.
- [Pi SDK 1.4.0](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/sdk.md) supplies the existing agent loop and file tools. Reuse that loop with a frozen pack rather than adding a second agent implementation.
- [Claw's upstream service manager](https://github.com/claw-eval/claw-eval/blob/main/src/claw_eval/runner/services.py) manages external service processes and reset endpoints; its full runner also supplies custom graders and recovery. Reuse frozen apps/fixtures through [FastAPI TestClient](https://fastapi.tiangolo.com/tutorial/testing/) for private ASGI lifecycle and keep Pi as the sole agent loop. This avoids a second server launcher and port-sharing state without claiming upstream grader/Pass^3 parity.
- [BigCodeBench's evaluator](https://github.com/bigcode-project/bigcodebench/blob/main/bigcodebench/eval/__init__.py) executes solution plus tests in a shared module and invokes unittest. [Inspect Evals](https://github.com/UKGovernmentBEIS/inspect_evals/tree/main/src/inspect_evals/bigcodebench) adds Docker sandboxing and a separate completion protocol. Reuse our Pi generation and private verification copy for the legacy instruct slice; do not import their agent/runtime stack or claim the Docker isolation and official scoring protocol.
- [Pinned DM task definitions](https://github.com/hwfengcs/DM-Code-Agent/blob/e4530be37e6f972d9735381e524cab4b5f732ddd/dm_agent/benchmarks/tasks.py) and [runner](https://github.com/hwfengcs/DM-Code-Agent/blob/e4530be37e6f972d9735381e524cab4b5f732ddd/dm_agent/benchmarks/runner.py) separate setup, visible/hidden verification and scope scoring. [Mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent) supplies the legacy loop; keep Pi as the single independent loop and reuse the pinned task contract rather than installing another agent runtime. The original source tests supply four concrete reference controls.
