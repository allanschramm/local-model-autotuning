# autoresearch — local runtime optimization

## Purpose
Bounded TPS × context tuning and protected local model processes. Quality evaluators, CLI dispatch and quality rankings are archived.

## Ownership
Repository developers.

## Local Contracts
- tuning.py owns finite Search, fixed-reference PPL admission and frontier checkpoints. core/search.py owns keys and adjacent Neighbors, not scores.
- core/llama_runner.py shares lifetime, RAM/VRAM monitoring and cleanup between native PPL and monitored generation. Preserve every preflight/watchdog guard.
- core/fingerprint.py owns portable files and explicit application; Search leaves Baseline and launcher selection untouched.
- SQLite tuning_runs/tuning_trials are canonical. Unrelated historical tables are preserved, never migrated or rescored.
- Imports work without quality or development packages.
- **Upstream-first (see `docs/llamacpp-toolset.md` + `docs/llamacpp-flags-audit.md` + root `AGENTS.md`):** Check `llama.cpp/common/arg.cpp` `add_opt` (`~310` flags) before adding any `ENGINE_*/SAMPLER_*` or gate — `90%` already exists upstream (`fit`/`fit-target`/`warmup`/`cache-ram`/`kv-unified`/`repack`/`swa-full`/`yarn`/`spec-ngram`/`dry`/`xtc`/`override-tensor`/`cpu-mask`/`poll`); harness is passthrough mapper — forward in `autoresearch/core/llama_runner.py` `_build_cmd` vs `arg.cpp`. Keep only host/WDDM/thermal/Pareto gates (`common/fit.h:14` assumes unlimited host, so `preflight_host_memory` + `SHARED 2048` kill are the keepers).
- **Flag-drift guard (mandatory on every engine bump):** `load_mode_flag(no_mmap, mlock)` in `autoresearch/core/llama_runner.py` is the **single** translator for Baseline `NO_MMAP`/`MLOCK` → `--load-mode MODE` (upstream #26934 removed `--mmap`/`--no-mmap`/`--mlock`; gone from b11149 *and* pinned `v0.5.0 arg.cpp`). Bijection: `F/F→mmap`, `F/T→mmap+mlock`, `T/F→none`, `T/T→mlock`. Default emits `mmap` explicitly, never `auto` (device-dependent). Never re-inline the mapping — runtime emitters share it (`llama_runner._build_cmd`, `runtime_measurements.run_llama_bench_validation`, `model_up.fingerprint_flags`, `serve-config.build_args`). `assert_flags_supported(cmd, binary)` probes `<binary> --help` (cached per path) and raises `FlagDriftError` naming the flag + `engine@tag` build, wired into server build, cli bench, `model_up` and `serve-config` (`serve` + `print-cmd`). Exemptions: `FORK_ONLY_FLAGS` (codacus `--moe-cache-*`) and an unprobeable binary (returns `None`, skips — never fails a Trial on a guess). Only **long** flags are validated. Help lines carry **multiple aliases in any order** (`-ngl,  --gpu-layers, --n-gpu-layers N`), **multi-char shorts** (`-ncmoe`, `-ctk`) and **dots in long flags** (`--fim-qwen-1.5b-default`): a naive one-flag-per-line or `[\w-]` parser yields false drift rejections, which is worse than no check. `LlamaServerRunner.__enter__` wraps `_start()` in `try/except BaseException` → `_cleanup_all()`, because `__exit__` never runs when the `with` body raises and the VRAM sampler would otherwise leak (also covers the RAM preflight reject). Baseline keys stay `NO_MMAP`/`MLOCK` — never migrate the store schema for a flag rename.
- Baseline `VRAM_LIMIT_MB` is the single VRAM budget for runtime preflight and runtime monitoring; there is no CLI override. `resolve_vram_limit_mb` **hard-clamps** to ``physical − PHYSICAL_VRAM_KEEPOUT_MB`` (default 256, operator-set 2026-09-04; 512 false-killed loads that fit). Overridable via env `AUTORESEARCH_PHYSICAL_VRAM_KEEPOUT_MB` — read inside `dedicated_vram_kill_ceil` so the preflight clamp and runtime monitor agree (8 GB-class dense @ 65k q4_0 sits ~7.7 GB steady-state; keepout 256 measured safe, peaks 7.4–7.8 GB, no Shared spill). Keep Baseline `NO_MMAP` when it wins TPS (emitted as `--load-mode none|mlock`, never the retired `--no-mmap`). **Anti-Shared:** (1) dedicated keepout + kill dense+MoE; (2) absolute Shared GPU kill (`SHARED_VRAM_LIMIT_MB`, default 2048) — MoE+`NO_MMAP` can hit Shared→pagefile with dedicated still ~4–5 GB; (3) `GGML_CUDA_NO_PINNED=1` on cli/server; (4) TPS `llama-cli` `-c` ≤ `BENCH_CTX_CAP`.
- VRAM preflight estimates main GPU-resident weights + configured `CTX_SIZE` KV + enabled external draft weights + conservative speculative/MTP workspace (`512 + 256 * SPEC_DRAFT_N_MAX` MiB) before server start. **KV:** `gguf_kv_f16_mb` — sliding-window arches (gemma4 SWA) charge `min(ctx, window)` + `key/value_length_swa` (not full-ctx × full dims; that false-rejected some MoE loads @ high ctx). **Exception (workspace):** MoE with `n_cpu_moe > 0` and an external draft file (e.g. `draft-dflash`) counts draft weights only — no flat speculative workspace (false-rejects DFlash on 8 GB-class when measured peaks fit). Pure n-gram statistical speculation (`is_pure_ngram_spec_type`) has 0 MB VRAM workspace (universal statistical lookup in host RAM, no neural speculative tensors). Embedded MTP (no draft file) and dense neural targets still use the workspace term. **Free clamp (opt-in):** the dense free−headroom clamp is OFF by default (operator decision 2026-09-04 — desktop reservations false-rejected loads that fit); `AUTORESEARCH_VRAM_FREE_CLAMP=1` restores `min(configured, free−headroom)`. MoE with `n_cpu_moe > 0` always uses configured only. The legacy `AUTORESEARCH_SKIP_FREE_CLAMP` env is retired (clamp already off). **Runtime kill guard (2026-09-04):** the monitor kills on CUDA-reported free memory (`cuMemGetInfo` via `hardware.cuda_free_mb`, primary ctx re-bound per call — contexts are per-thread) dropping below `AUTORESEARCH_CUDA_FREE_FLOOR_MB` (default 256 MiB); NVML `used` (counts committed-but-evictable desktop memory) is a peak-metric + fallback only, active when the probe misses 5 consecutive samples. **Runtime VRAM kill (dense + MoE):** dedicated `used > min(VRAM_LIMIT_MB, physical − keepout)` **or** process Shared GPU `> SHARED_VRAM_LIMIT_MB`. **TPS `llama-cli`:** `-c` capped at `BENCH_CTX_CAP` (4096); full Trial CTX only on the monitored server; cli has dedicated + Shared watchdogs. Never raise `VRAM_LIMIT_MB` above physical VRAM to clear a bad estimate.
- Host-memory gate lives in `autoresearch/core/hardware.py` + `preflight_host_memory` in `llama_runner.py`: discrete + n-cpu-moe>0 charges expert-class tensor bytes only (`ram_resident_bytes_mb` via `gguf_expert_bytes_mb`; draft/KV stay on GPU; fallback file×0.72 when the header cannot be read); otherwise full GGUF (+ draft + KV). Unified headroom `max(6144, 0.20×RAM)` MiB; discrete `max(4096, 0.15×RAM)` (NVIDIA CUDA and AMD ROCm/Radeon). Override `HOST_MEMORY_HEADROOM_MB` / `AUTORESEARCH_HOST_HEADROOM_MB`.
- Do not add hardcoded user or absolute directory paths in the source files.
- Model paths: `resolve_model_file` in `model_arch.py` owns flat + nested (`publisher/model/*.gguf`) lookup; `resolve_model_path` in `llama_runner.py` wraps it (missing → `models_dir/ref` for callers to fail later). Config Baseline keeps basenames (and `draft/...` for drafts).
- Architecture class (MoE vs dense): `autoresearch/core/model_arch.py` reads local GGUF metadata (`expert_count` / `*moe*` arch). No filename heuristics. Model cards must mirror that GGUF truth. Agents query it via `scripts/model_info.py <basename>` (read-only, harness-backed) — never parse the raw `.gguf` or scrape tensor dumps. **Unreadable metadata fails closed:** `GGUFMetadataError` raises instead of reporting "dense" — a missing `gguf` package (wrong interpreter) or a corrupt header must never silently drop `--n-cpu-moe`, because that puts every expert on the GPU and WDDM spills the overflow into Shared GPU memory (measured on an 8 GB-class card: ~14 GB GGUF on 8 GB VRAM → ~9 GB Shared). Only a *missing file* resolves to not-MoE.
- MoE `N_CPU_MOE=None` → `resolve_n_cpu_moe` sets `--n-cpu-moe` to GGUF `block_count` (replaces old `override-tensor .*exps.*=CPU`). Explicit `0` = full GPU; `N>0` = manual.
- GPU/CPU split: `N_GPU_LAYERS` in Baseline (`-1` = Auto, `0` = CPU-only, `N>0` = N layers on GPU) and `NUMA` (`None` / `distribute` / `isolate`) are validated in `validate_config` and are passed through by the runtime runners. CPU-only Baseline is first-class via `N_GPU_LAYERS=0`.
- **Single-load gate (issue #41)**: `autoresearch/core/single_load.py` refuses a second full server while one is live on a harness port (`SingleLoadError`, reuses the #37 detection surface). Wired into `LlamaServerRunner.__enter__` and `SGLangServerRunner.start` before the orphan sweep; a speculative draft on the same server never counts. Fail-open like the sweep: a detection failure logs and proceeds. Bypass via `AUTORESEARCH_ALLOW_MULTI_SERVERS=1` (also skips the sweep so a live sibling is not killed).
- **SGLang lifecycle + trust-remote-code**: the SGLang runner composes `PR_SET_PDEATHSIG` with its `os.setsid` preexec (no orphan on abrupt parent death) and escalates teardown terminate → grace → SIGKILL. `--trust-remote-code` is opt-out via `SGLANG_TRUST_REMOTE_CODE=0` (default on, matches legacy behavior) for non-self-curated checkpoints.
