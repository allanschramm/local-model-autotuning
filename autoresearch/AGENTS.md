# `autoresearch/` — Core Autotuning Package

## Purpose
Core codebase containing search strategy optimization logic, llama.cpp server wrappers, API client integrations, and evaluation benchmark harnesses (Nexus, Claw, Coding, SWE-lite agentic coding).

## Ownership
Repository developers.

## Local Contracts
- Do not modify internal evaluation logic or benchmarks under `autoresearch/benchmarks/` without authorization.
- **Upstream-first (see `docs/llamacpp-toolset.md` + `docs/llamacpp-flags-audit.md` + root `AGENTS.md`):** Check `llama.cpp/common/arg.cpp:1424` `add_opt` (`~310` flags) before adding any `ENGINE_*/SAMPLER_*` or gate — `90%` already exists upstream (`fit`/`fit-target`/`load-mode`/`warmup`/`cache-ram`/`kv-unified`/`repack`/`swa-full`/`yarn`/`spec-ngram`/`dry`/`xtc`/`override-tensor`/`cpu-mask`/`poll`); harness is passthrough mapper — forward in `autoresearch/core/llama_runner.py:895 _build_cmd` vs `arg.cpp`. Keep only host/WDDM/thermal/Pareto gates (`common/fit.h:14` assumes unlimited host, so `preflight_host_memory:662` + `SHARED 2048` kill are the keepers).
- `autoresearch/core/config.py` owns the mutable Baseline (`ENGINE_DEFAULTS` / `SAMPLER_DEFAULTS`) and validation. File is **gitignored**; seed from `config.py.example`. Before the first Trial on a model, seed `SAMPLER_DEFAULTS` from `docs/models/<card>.md` Recommended settings for the job (agentic/general vs coding). The ignored `.autoresearch_state.json` stores visited memory only. `TPS_FLOOR` (default 20.0) is the only Trial reject gate for throughput — set per model (MoE on 8GB often needs 15–18).
- Baseline `VRAM_LIMIT_MB` is the single VRAM budget for autoloop preflight and runtime monitoring; there is no CLI override. `resolve_vram_limit_mb` **hard-clamps** to ``physical − PHYSICAL_VRAM_KEEPOUT_MB`` (default 256, operator-set 2026-09-04; 512 false-killed loads that fit). Overridable via env `AUTORESEARCH_PHYSICAL_VRAM_KEEPOUT_MB` — read inside `dedicated_vram_kill_ceil` so the preflight clamp and runtime monitor agree (8 GB-class dense @ 65k q4_0 sits ~7.7 GB steady-state; keepout 256 measured safe, peaks 7.4–7.8 GB, no Shared spill). Keep Baseline `NO_MMAP` when it wins TPS. **Anti-Shared:** (1) dedicated keepout + kill dense+MoE; (2) absolute Shared GPU kill (`SHARED_VRAM_LIMIT_MB`, default 2048) — MoE+`NO_MMAP` can hit Shared→pagefile with dedicated still ~4–5 GB; (3) `GGML_CUDA_NO_PINNED=1` on cli/server; (4) TPS `llama-cli` `-c` ≤ `BENCH_CTX_CAP`.
- VRAM preflight estimates main GPU-resident weights + configured `CTX_SIZE` KV + enabled external draft weights + conservative speculative/MTP workspace (`512 + 256 * SPEC_DRAFT_N_MAX` MiB) before server start. **KV:** `gguf_kv_f16_mb` — sliding-window arches (gemma4 SWA) charge `min(ctx, window)` + `key/value_length_swa` (not full-ctx × full dims; that false-rejected some MoE loads @ high ctx). **Exception (workspace):** MoE with `n_cpu_moe > 0` and an external draft file (e.g. `draft-dflash`) counts draft weights only — no flat speculative workspace (false-rejects DFlash on 8 GB-class when measured peaks fit). Pure n-gram statistical speculation (`is_pure_ngram_spec_type`) has 0 MB VRAM workspace (universal statistical lookup in host RAM, no neural speculative tensors). Embedded MTP (no draft file) and dense neural targets still use the workspace term. **Free clamp (opt-in):** the dense free−headroom clamp is OFF by default (operator decision 2026-09-04 — desktop reservations false-rejected loads that fit); `AUTORESEARCH_VRAM_FREE_CLAMP=1` restores `min(configured, free−headroom)`. MoE with `n_cpu_moe > 0` always uses configured only. The legacy `AUTORESEARCH_SKIP_FREE_CLAMP` env is retired (clamp already off). **Runtime kill guard (2026-09-04):** the monitor kills on CUDA-reported free memory (`cuMemGetInfo` via `hardware.cuda_free_mb`, primary ctx re-bound per call — contexts are per-thread) dropping below `AUTORESEARCH_CUDA_FREE_FLOOR_MB` (default 256 MiB); NVML `used` (counts committed-but-evictable desktop memory) is a peak-metric + fallback only, active when the probe misses 5 consecutive samples. **Runtime VRAM kill (dense + MoE):** dedicated `used > min(VRAM_LIMIT_MB, physical − keepout)` **or** process Shared GPU `> SHARED_VRAM_LIMIT_MB`. **TPS `llama-cli`:** `-c` capped at `BENCH_CTX_CAP` (4096); full Trial CTX only on the monitored server; cli has dedicated + Shared watchdogs. Never raise `VRAM_LIMIT_MB` above physical VRAM to clear a bad estimate.
- Host-memory gate lives in `autoresearch/core/hardware.py` + `preflight_host_memory` in `llama_runner.py`: discrete + n-cpu-moe>0 charges expert-class tensor bytes only (`ram_resident_bytes_mb` via `gguf_expert_bytes_mb`; draft/KV stay on GPU; fallback file×0.72 when the header cannot be read); otherwise full GGUF (+ draft + KV). Unified headroom `max(6144, 0.20×RAM)` MiB; discrete `max(4096, 0.15×RAM)` (NVIDIA CUDA and AMD ROCm/Radeon). Override `HOST_MEMORY_HEADROOM_MB` / `AUTORESEARCH_HOST_HEADROOM_MB`.
- Do not add hardcoded user or absolute directory paths in the source files.
- Model paths: `resolve_model_file` in `model_arch.py` owns flat + nested (`publisher/model/*.gguf`) lookup; `resolve_model_path` in `llama_runner.py` wraps it (missing → `models_dir/ref` for callers to fail later). Config Baseline keeps basenames (and `draft/...` for drafts).
- Fingerprint file bus (ADR 0014, issue #49): `autoresearch/core/fingerprint.py` owns dump/load/apply of the machine-local JSON (`schema_version` + GGUF basename + engine, optional sampler) under gitignored `fingerprints/`; basename-only, no private paths/hostnames/emails/aliases/GPU SKUs. Not the `pareto.py` hash. `apply()` (issue #50) copies engine (+ sampler when present) into Baseline via `write_baseline` — `scripts/apply_fingerprint.py` is the one command; benches keep reading Baseline. Kept TPS+PPL Neighbors (issue #51) write the engine-only file via `autoloop.write_climb_fingerprint` at the same moment as the Baseline + alias sync; rejected/failed climbs and non-TPS modes never touch it. `SERVER_ENGINE_KEYS` / `HARNESS_ONLY_ENGINE_KEYS` live here (single source; `scripts/model_up.py` imports both). A Trial (`handle_single_run`, issue #53) rejects (`MODEL_REJECTED`, never a score) when the file exists and its server flags differ from the live Baseline via `fingerprint.mismatch_reason`; missing file = Baseline-only behavior, harness-only drift never rejects.
- Architecture class (MoE vs dense): `autoresearch/core/model_arch.py` reads local GGUF metadata (`expert_count` / `*moe*` arch). No filename heuristics. Model cards must mirror that GGUF truth. Agents query it via `scripts/model_info.py <basename>` (read-only, harness-backed) — never parse the raw `.gguf` or scrape tensor dumps.
- MoE `N_CPU_MOE=None` → `resolve_n_cpu_moe` sets `--n-cpu-moe` to GGUF `block_count` (replaces old `override-tensor .*exps.*=CPU`). Explicit `0` = full GPU; `N>0` = manual.
- GPU/CPU split: `N_GPU_LAYERS` in Baseline (`-1` = Auto, `0` = CPU-only, `N>0` = N layers on GPU) and `NUMA` (`None` / `distribute` / `isolate`) are validated in `validate_config` and surface through autoloop `CORE_PASSTHROUGH` (issue #16). CPU-only Baseline is first-class via `N_GPU_LAYERS=0`.
- **Trial order (hard gate):** GGUF arch classify → resolve `N_CPU_MOE` → VRAM preflight → **host-memory preflight** (full GGUF + KV, no MoE shrink) → TPS floor → eval. MoE `N_CPU_MOE=0` that exceeds physical VRAM is `MODEL_REJECTED` (set `None` for auto offload). Dense never uses expert offload. Host gate rejects oversized unified-RAM loads (`HOST_MEMORY_PREFLIGHT`) before Metal/CUDA start.
- **Watchdog policy kills are `WATCHDOG_KILL`, never `MODEL_REJECTED` (issue #72):** runtime VRAM-guard kills (CUDA-free floor, NVML-used fallback, absolute Shared) record `TrialOutcome.WATCHDOG_KILL` with `scope=cuda_free|nvml-used|shared` in the diagnostic (`LlamaServerRunner.vram_kill_reason`); preflight/`N_CPU_MOE=0`/TPS-floor rejects stay `MODEL_REJECTED`. Status stays `rejected` (out of the front either way) — only the outcome/diagnostic become honest. Legacy `MODEL_REJECTED`/`VRAM_LIMIT_EXCEEDED` rows relabel via `scripts/recompute_status.py --relabel-watchdog` (`run.relabel_watchdog_kills`, idempotent).
- **No autonomous autoloop on user request:** When the user asks for a trial, hill climb, bench, validate, or any tuning/eval action, run the explicit harness (`benchmark_search.py`, `python -m autoresearch.runners.run`) — do **NOT** launch `autoloop.py` / the `/autoresearch` autonomous loop. `autoloop.py` is operator-only; the user starts the background hill-climb themselves.
- **Use the harness, not raw binaries**: Run `benchmark_search.py` (or `autoloop.py` only when the operator starts it) for evaluation. Do not invoke `llama-server` or `llama-bench` directly — the harness resolves paths (supporting both `build-cuda` and `build-cpu`), translates config flags to CLI args, manages server lifecycle, monitors VRAM, and logs results.
- **Permanent RAM circuit breaker (`autoresearch/core/circuit_breaker.py`, always on)**: every model spawn in this repo runs a RAM watchdog — kills the process tree when free RAM < `FREE_RAM_FLOOR_MB` (default 500, operator-set 2026-08-25) or the watched process RSS > physical − `RAM_WATCHDOG_RESERVE_MB` (default 4096) — and `preflight_ram` refuses launches that cannot fit (resident bytes — expert tensors for offloaded MoE, via `ram_resident_bytes_mb` — + workspace + 512 MiB launch margin). No disable switch; thresholds live in `autoresearch/core/circuit_breaker.py` (single source; config keys reference it). **Harness-only since 2026-08-26**: `scripts/model_up.py` alias launches are exempt (operator decision — aliases are trusted hand-tuned recipes; the detached watchdog's probe subprocesses popped terminal windows on Windows 11). Raw llama launches outside the harness/launcher are forbidden (2026-08-25: a raw llama-cli with stock defaults ballooned to a 22.4 GB working set and thrashed swap). **Claw/agentic loop:** merge `reasoning_content` when `content` is empty (same as coding-10) and pass `max_tokens≥4096` for agentic tiers — thinking models otherwise get blank graders + mid-loop HTTP 400; 1.5-class CoT still exhausts 2048 mid-`<think>` (`n_decoded = 2048` exactly), so the floor was raised 2048→4096 on 2026-08-19. Per-turn urlopen timeout is **420 s** (was 30 s → 240 s — reasoning `<think>` traces + max_tokens exceed 30 s at ~40–55 t/s and truncated turns; Ornith-1.5-9B agentic 0.2667 → 0.8000 after the 30→240 s fix; slow CPU-offloaded MoE rigs need up to 240 s per 2048-token turn, 420 s per 4096-token turn). **Observability:** per-run artifacts live in `autoresearch/runners/logs/` (gitignored, keep last 20): `llama-server-<UTC>-<model>.log` (rotated per Trial; the old shared `llama_server.log` was wiped every run) and `agentic-<UTC>-<model>.json` (per-task score/rubric/report-length/turns/`length_stops`/`http_errors`). HTTP 400/500 bodies are printed with the error; `finish_reason=length` (max_tokens exhausted) is counted per task. **`REASONING_PRESERVE`:** Baseline engine knob (`None` = template default; `True`/`False` = `--reasoning-preserve` / `--no-reasoning-preserve`). Seed from the card only when `GET /props` `chat_template_caps.supports_preserve_reasoning` is true — not a Search neighbor; coding-10 is single-shot. **Coding-10 sandbox:** `_run_subprocess` always uses a private temp `cwd` — BigCodeBench tasks (e.g. `files.zip`) and bad solutions must not write into the repo root.
- **Status recompute after every Trial write (issue #5)**: `run.py` / `autoloop.py` refresh the whole store's statuses after each write via `autoresearch/core/recompute.py` (pure, idempotent). Domination is same-model only (ADR 0017): recompute groups rows by basename × budget bucket and labels every complete basename vector `on_front` — no group ever demotes another, and legacy cross-model `dominated` labels flip to `on_front` via the normal pass. `scripts/recompute_status.py` runs the same refresh retroactively (default scope `model`; `bucket` retained as an accepted argument form with the same same-basename competition). Rejected rows and Morris screen probes never compete; fingerprint-less legacy rows recompute by basename. **Budget bucket** = `round(VRAM_LIMIT_MB/1024)` from `config_json` (intended limit); peak `memory_gb` is legacy fallback only — same-Fingerprint Trials with different peaks must still merge. Same-model config A/B verdicts (`dominated`) live in hill-climb bookkeeping (`search.py` neighbor acceptance), not store-wide recompute.
- **Perplexity-Guided Tuning Guard**: When using `--perplexity-val` to maximize throughput (TPS), enforce a strict quality ceiling: any candidate configuration resulting in more than a 1% increase in perplexity (PPL) compared to the baseline must be discarded.
- **Single-load gate (issue #41)**: `autoresearch/core/single_load.py` refuses a second full server while one is live on a harness port (`SingleLoadError`, reuses the #37 detection surface). Wired into `LlamaServerRunner.__enter__` and `SGLangServerRunner.start` before the orphan sweep; a speculative draft on the same server never counts. Fail-open like the sweep: a detection failure logs and proceeds. Bypass via `AUTORESEARCH_ALLOW_MULTI_SERVERS=1` (also skips the sweep so a live sibling is not killed).
- **SGLang lifecycle + trust-remote-code**: the SGLang runner composes `PR_SET_PDEATHSIG` with its `os.setsid` preexec (no orphan on abrupt parent death) and escalates teardown terminate → grace → SIGKILL. `--trust-remote-code` is opt-out via `SGLANG_TRUST_REMOTE_CODE=0` (default on, matches legacy behavior) for non-self-curated checkpoints.
- **Results store (SQLite canonical, TSV legacy fallback)**: `results.db` (SQLite, gitignored) is the canonical Trial store — typed columns, indexed, keyed by `trial_id`. `results.tsv` (append-log) is the legacy fallback, still written on every Trial (best-effort) and kept in sync so either store can rebuild the other. Reads prefer the DB and fall back to the TSV when it is missing or unseeded (`results_db.load_rows` / `store_rows`). Writes: DB upsert first (primary), TSV append second; a DB failure logs and the TSV still captures the row (heal via `try_sync_from_tsv`), and only a double failure raises. `recompute_statuses()` refreshes statuses in both stores inside the results lock after every call. Maintenance/parity: `scripts/rebuild_results_db.py` (`--force` reseed DB from TSV, `--rebuild-tsv` rewrite TSV from DB). Never hand-edit either store except documented gambiarra scripts. Reasoning knobs are flat DB columns since 2026-08-29 (`reasoning_budget` REAL / `reasoning_effort` TEXT, derived from each row's `config_json`, one-shot marker-guarded backfill; legacy TSV rows keep the knobs inside `config_json` only — `results_db._cells` re-derives them on every insert).
